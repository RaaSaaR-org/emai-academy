## 2. Structure

```
content/
  skills/*.yml               9 root skills, 21 sub-skills (sync_skills.py format)
  courses/*.yml              21 courses, price 0, de + translations.en, 1 learning path each
  rooms/*.yml                authoring source: one file per learning path (bilingual leaves {de, en})
  learning_rooms.json        GENERATED by tools/build_learning_rooms.py (21 paths, 55 units)
  character_areas.json       one area "physical-ai", include_unassigned_roots, 5x5
  lectures/                  MP4_LECTURES root (empty)
  tools/build_learning_rooms.py
  tools/validate.py
  tools/verified_videos.json 10 YouTube ids verified via oEmbed (HTTP 200) + watch-page lengthSeconds
  README.md
```

**Why there is a generator:** the guided-lesson `completion.answer` has to equal
`{checkId: answer}` for every check, in both de and en. Authors therefore write each step once.
The text leaves are `{de, en}`, and the ids, option values, answers and code are shared. The
builder derives `completion.answer`, so de, en and the answer can't drift apart.
`build_learning_rooms.py --check` fails if the JSON is stale.

**XP:** rooms never award XP. Only completing a lecture gives XP (10 per linked sub-skill).
The 9 courses with a YouTube section can therefore move the skill tree. The other 12 courses
are room-only and give no XP. That is a known limitation of the upstream model. Once EmAI has
its own recorded videos, adding an mp4 section (`MP4_LECTURES/<course>/<lecture>.mp4`) fixes it.

**Videos:** all YouTube ids are in `content/tools/verified_videos.json`. For each one I checked
that oEmbed returns HTTP 200 and read the real `lengthSeconds` from the watch page. The
validator rejects any id that isn't on that list, and any duration that doesn't match. I chose
official channels where they exist (NVIDIA Omniverse, Google for Developers). None of the videos
is an official Unitree or Physical Intelligence upload: I didn't find one that I could verify and
that also fit house style. All videos are in English, and the titles in the courses say so.

**Decider path for skill 1:** `physical-ai-grundlagen` follows the 8 chapters of "Physical AI
in acht Kapiteln" from the landing page (`src/i18n/locales/{de,en}/knowledge.json`), one
chapter each. The chapter texts and takeaways are used almost verbatim and extended with checks
and two slider experiments. It closes with a 5-question knowledge check.

**Builder start for skills 3 and 4:**

- `so101-lerobot-setup`: install, find ports, set motor IDs, calibrate, kinematics,
  teleoperate. Commands come from the LeRobot docs (`so101.mdx`, `il_robots.mdx`).
- `lerobot-datensaetze`: `lerobot-record`, the v3.0 layout, the custom episode reader, an
  episode-quality "detective", and variety over volume. The last two use the vla-training
  findings: 402 episodes of a single scene, a 2 % brightness spread, a sim image 11 σ away,
  and Lin et al.'s rule of thumb of about 50 demonstrations per environment-object pair.

Content sources: the landing-page knowledge and glossary, `emai/vla-training` (README,
`docs/vla-modelle.md`, `docs/datensatz-erweitern.md`, `docs/lehren.md` L49), the LeRobot docs in
`emai/repos/lerobot` (so101, il_robots, lerobot-dataset-v3, smolvla, async), and the SO-101
URDF for link lengths. The house style holds throughout: "kognitive Roboter", no "humanoid"
(the validator checks this), vendor-neutral, human-first.

## 3. Custom lesson module contract

This is the contract agreed with `content/modules/` (that README is the source of truth; the
modules were already built when I aligned to them):

| Unit | `module_id` | Registry descriptor (built) | `completion.answer` (must be exact) | `content.<lang>` passed |
|---|---|---|---|---|
| `so101-kinematik` | `robot-arm-kinematics` | `content/modules/dist/descriptors/robot-arm-kinematics.json` → `http://localhost:3001/learning-modules/<sha>/index.js` | `{"reached": true}` | `title`, `intro`. Geometry and targets are the module defaults: links 116/135/95 mm, two target zones, zone B needs a pitch of -90° ± 15° |
| `ds-episode-lesen` | `teleop-dataset-explorer` | `content/modules/dist/descriptors/teleop-dataset-explorer.json` | `{"fps": 30, "lagging_joint": "elbow_flex", "gripper_gap": "contact"}` | `title`, `intro`. The episode data and questions are bundled in the module |

- The answer each module posts is fixed in `rooms/*.yml` as `completion_answer`.
  `validate.py` (`MODULE_ANSWERS`) checks it against the contract and validates the built
  descriptors.
- The served path is `/learning-modules/` (copied into `frontend/public/learning-modules/`),
  not `/lesson-modules/`.
- Each module must be registered with `python -m api.register_lesson_module <descriptor>`.
  Until then, both units return 503.
- If a module's answer or content fields change, update `MODULE_ANSWERS` and the unit
  together.

## 4. Validation

```sh
cd /Users/sebastian/develop/Bootstrap-Academy/emai-academy
../skills-ms-rooms/.venv/bin/python content/tools/build_learning_rooms.py          # regenerate JSON
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=../skills-ms-rooms \
  ../skills-ms-rooms/.venv/bin/python content/tools/validate.py                     # -> "content is valid"
# upstream skill check on its own (same result):
cd ../skills-ms-rooms && COURSES=$PWD/../emai-academy/content/courses \
  DATABASE_URL=postgresql+asyncpg://academy@127.0.0.1:5432/emai_skills \
  .venv/bin/python scripts/sync_skills.py --list ../emai-academy/content/skills    # exit 0
```

- `poe check` can't be used, because it is hard-wired to the upstream `config/skills`.
- The validator must run with the `skills-ms-rooms/.venv`. The Bootstrap `skills-ms/.venv`
  lacks `greenlet`, so importing `api.database` fails there.
- The validator opens no DB connection and writes nothing into the worktree.

Current result: all 10 checks pass. That covers the catalogue, the 21 courses, the derived
curricula, the answer consistency, 9 skills and 21 sub-skills with exactly one link per course,
the area, both custom units matching the module contract with valid descriptors, the 10
verified YouTube ids, and house style.

## 5. Open points / limitations

- The running EmAI skills-ms still serves the placeholder. Run `scripts/reload-content.sh`:
  restart, `sync_skills`, register modules, positions.
- 12 room-only courses give no XP (see 2.2).
- Skill 7 has the OR dependency described in 2.1.
- There is no explicit `curriculum`, so every course uses the derived one. Section titles
  (`Vortrag`, `Video`) are plain strings and are shown untranslated in en.
- Videos are English only. YouTube availability can change, so re-run the oEmbed check
  before a demo.
- Legal and regulatory statements (ISO 10218, ISO/TS 15066, ISO 12100, IEC 62443, EU
  2023/1230 from 20 Jan 2027, AI Act, CRA, § 87 (1) no. 6 BetrVG) are summaries and are
  marked "not legal advice" in the course. They should get an expert review before going
  public.
